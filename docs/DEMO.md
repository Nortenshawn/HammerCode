# HammerCode 最终视频与现场演示检查单

原始题目要求视频为 MP4、2 分钟以内、不超过 200 MB。最终视频只展示一个完整真实编程闭环，不尝试塞入所有功能。

## 演示前

- 使用 Apple Silicon macOS，确认正式应用能连接演示模型。
- 从 `.env.example` 创建未入库 `.env`；录屏前关闭编辑器、终端历史、系统通知和可能暴露 key 的窗口。
- 运行 `npm run typecheck`、`npm test`、`npm run build`，确认最终提交版本通过。
- 在 `/Users/norten/Developer/HammerTest` 准备一个可丢弃的小型失败测试夹具，只包含 1 个实现文件、1 个测试文件和无外部依赖的测试命令。
- 预演至少两次并记录实际模型耗时；模型等待较长部分可以加速或剪辑，但工具意图、审批、真实命令结果和最终状态不能伪造。
- 确认输入区选中“请求批准”，避免视频中普通写入自动跳过审批。

## 推荐任务

```text
阅读当前项目，定位失败测试的根因，做最小修改并运行测试验证。先建立计划，不要改动无关文件。
```

夹具应让模型通过一次 `read_file`、一次 `edit_file` 和一次确定的本地测试完成。不要在最终视频中临时挑战破坏性命令或复杂长任务。

## 110 秒时间轴

### 0–12 秒：项目与目标

画面：HammerCode 主界面和已选择的演示工作区。

口述：

> HammerCode 是我用 Electron 和 TypeScript 独立实现的本地编程智能体。每条聊天绑定一个工作区，模型只能提出工具调用，不能直接操作系统。

### 12–28 秒：提交真实任务

画面：输入推荐任务并发送，短暂展示 Fast/Strong 与“请求批准”。

口述：

> 每个 turn 会固化模型、权限和预算；复杂任务在副作用前必须建立显式计划。

### 28–48 秒：只读分析

画面：Plan、`list_files`/`read_file`、模型定位失败原因。等待部分可加速。

口述：

> 只读工具在工作区真实路径校验后自动执行，文本、思考、工具参数和结果都流式记录。

### 48–72 秒：diff 审批与写入

画面：`edit_file` 审批面板，停留足够看清目标路径和红绿 diff，然后批准。

口述：

> 文件修改先生成可审计 diff。批准后仍会复查 SHA-256，防止审批等待期间覆盖外部编辑，再通过临时文件和原子替换落盘。

### 72–92 秒：真实验证

画面：本地测试工具卡，展示 command、cwd、exit code 0 和通过数量。

口述：

> 命令有工作区 cwd、超时、输出上限和取消能力；安全的本地测试可自动执行，远端和复合命令仍会升级审批，高风险操作直接阻断。

### 92–110 秒：结果与设计收尾

画面：最终 Markdown 总结、累计 diff、工具授权来源。

口述：

> 工具结果会回传模型继续推理，直到明确完成或触发预算、错误、取消等终止条件。会话可恢复，但历史工具不会在继续聊天或重启时重放。

## 剪辑和导出

- 分辨率建议 1920×1080 或 1440×900，保证 diff 和命令文字可读。
- 使用 30 fps 即可；等待模型的空白区段可 2–4 倍加速。
- 保留一次真实发送、一次真实审批、一次真实命令结果和最终完成状态的连续因果关系。
- 导出 H.264 MP4；完成后核对时长小于 120 秒、文件小于 200 MB、声音清楚。
- 从头播放成片一次，逐帧检查没有 `.env`、API key、Bearer header、系统用户名隐私、无关通知或剪辑残帧。

## 不要放入最终视频

- 不打开 `.env`、设置存储、会话 JSON 或开发者工具 Network 面板。
- 不展示 13 个功能的走马灯；BTW、项目记忆、Skill、归档和子任务只在评委追问时说明。
- 不执行 `sudo`、擦盘、关机、远端 push 或其他危险命令来“证明”安全；自动测试和在线报告已经覆盖代表性阻断。
- 不声称任意 Shell 已被绝对证明安全，不声称未签名目录包可直接公开分发。

## 提交压缩包检查

- 最终文件为 `README.txt` 和 MP4，不把 Git 仓库、`.env`、`.app`、PDF 题目或测试沙箱放进 zip。
- zip 使用本人姓名命名。
- `README.txt` 中的 GitHub 地址可以公开访问，仓库提交历史完整。
- 截止时间：2026 年 9 月 2 日 24:00（北京时间）；截止后停止向公开仓库推送。
