# HammerCode 演示检查单

## 演示前

- 确认设备为 Apple Silicon macOS，网络可访问配置的 API endpoint。
- 从 `.env.example` 创建本地 `.env`，只填写演示用 API key；不要投屏展示或打开 `.env`。
- 运行 `npm run typecheck && npm test && npm run build`，确认全部成功。
- 准备一个可丢弃的演示工作区，不要选择包含真实凭据或私密资料的目录。

## 推荐演示脚本

1. 在左侧添加两个演示项目，说明每条聊天仍绑定单一工作区，renderer 没有任意文件或 Shell 权限。
2. 输入：“阅读这个项目，给 README 增加一段运行说明，并运行测试验证。”
3. 展示只读工具自动执行及聊天内实时展开的思考、工具调用链。
4. 写入请求出现时展开 diff，先拒绝一次，展示 agent 把拒绝作为可恢复结果处理。
5. 再次提出任务并批准写入，展示文件结果。
6. 命令请求出现时指出完整 command、cwd 和 timeout，再批准测试。
7. 展示退出码、耗时、输出，以及任务完成后本轮过程自动折叠、最终总结按 Markdown 渲染。
8. 不新建聊天，直接追问：“保留刚才的修改，再补一个 Windows 不适用的说明。”展示同一聊天新增一轮，旧工具调用没有被重放。
9. 展开“改动审查”，展示右侧并排代码审查栏、红绿行差异，以及同一文件多次修改被合成从初始状态到当前状态的累计 diff。
10. 点击“撤销最近修改”，展示反向 diff 和二次审批；批准后确认文件恢复、记录标记为已撤销。
11. 直接点击项目文件夹右侧的 `+` 新建第二条聊天；发起只读任务后立刻切换到另一项目，再切回确认任务继续流式运行。
12. 展示 Fast / Strong 和“请求批准 / 完全访问”选择；强调设置按聊天保存、每轮固化，运行中不可切换。
13. 发起一个长任务并使用输入框右下角的“停止任务”，展示会话进入 cancelled；顶部只显示非交互运行状态，避免窄宽度误触。随后在同一聊天发送“不要继续执行，只总结目前状态”，展示 cancelled 会话可安全继续。

## 安全用例

可让模型尝试读取 `../outside.txt` 或运行 `sudo ...`。前者应作为路径逃逸阻断，后者应在审批前直接阻断。不要在真实机器上构造破坏性命令来验证规则；自动测试已覆盖代表性模式。

## 已知演示边界

当前不建设完整代码编辑器、MCP、插件或多 agent 并行编排。自动撤销只覆盖经 HammerCode 文件工具完成的、大小不超过 1 MB 的文本创建/替换/删除，不覆盖命令造成的任意文件变化。答辩重点应放在多 turn 状态机、历史副作用不重放、审批闭环、路径安全、多工作区绑定、累计 diff、撤销并发检查和崩溃恢复，以及这些关键分支的测试证据。
