# HammerCode 迭代开发状态

最后更新：2026-08-29

## 当前结论

HammerCode 已完成 Phase 9 项目长期记忆与受限多 Agent。每个工作区拥有独立、带来源/置信/失效条件的跨聊天记忆；主 Agent 可并发派出最多三个独立只读或补丁提案子任务，但子 Agent 不能递归编排、运行通用命令、直接写文件、访问审批或扩大父权限。实际文件写入仍由主 Agent 独占，并受路径租约、原审批策略、哈希复查和远端操作强制审批保护。核心闭环仍完全由项目自行实现，不依赖 agent 框架或服务端托管工具。

### 阶段二：连续对话、变更审查与撤销

- 同一聊天支持多个 turn；`completed`、`cancelled`、`failed` 都可由新的用户输入安全继续。
- 所有消息、工具轨迹和状态转换带 turn 归属，界面逐轮呈现。
- 恢复时闭合未完成 tool call，并保证历史工具永不自动重放。
- 已批准的文本文件创建、修改和删除形成可逆 `FileChange` 记录。
- 按文件合并多次变更，展示从首次 before 到当前有效状态的累计 diff；代码差异在不遮挡聊天的并排审查栏中显示。
- 撤销生成反向 diff 并再次审批；通过路径顺序、磁盘哈希和执行前复查阻断过期撤销。
- 撤销中断后只做磁盘状态对账，不重放反向副作用。

### 阶段九：项目长期记忆与受限多 Agent

- 状态：已完成（2026-08-29）。
- 项目记忆按工作区真实路径隔离持久化，记录类型、主题、陈述、置信级别、来源、冲突和失效条件。成功文件修改自动形成哈希绑定事实，验证结果绑定工作区修订；外部编辑或后续文件修改会使对应旧事实失效。
- 每轮请求只注入有界、相关、带来源的不可信记忆；模型可以检索和记录明确标为 `model_inference` 的决定/约束，不能伪造工具核验。设置页可查看有效/冲突/失效状态并软删除记录。
- 主 Agent 单个 turn 累计最多创建三个子任务。子任务拥有独立状态、Plan、模型、权限快照、轮次/工具/时间/上下文预算、消息审计和结构化结果；父任务停止会取消全部活动子任务，重启后不会续跑或重放。
- 首轮子 Agent 只允许计划、目录/文件/PDF读取、搜索和只读 Git；不存在递归编排、通用命令、项目记忆或直接写入工具。`patch_proposal` 只能生成带 before/after hash 的候选 diff，不落盘。
- 主写入与补丁提案共享规范化路径租约，同一路径同一时刻只能有一个 owner；拒绝、失败、取消和完成都会释放。主 Agent 的真实写入继续经过审批/完全访问、过期哈希与工作区边界，远端命令即使完全访问也始终逐次审批。
