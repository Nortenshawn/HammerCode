# HammerCode 迭代开发状态

最后更新：2026-08-28

## 当前结论

HammerCode 已从可完成单次任务的 MVP，演进为可在单工作区中维护多条独立聊天、并在每条聊天内连续追问的本地 coding agent。核心闭环、审批安全、恢复语义、文件变更审查与安全撤销均由项目自行实现，不依赖 agent 框架或服务端托管工具。

## 版本演进

### 阶段一：本地 Agent MVP

- 完成 DeepSeek V4 Flash 的 OpenAI-compatible 流式模型接入。
- 自行实现 agent 循环、分片 tool call 组装、上下文预算、状态机和终止条件。
- 完成本地文件与命令工具、工作区边界、审批、取消、超时和输出截断。
- 建立 Electron main/preload/renderer 安全边界和自动测试基线。

### 阶段一·五：产品化界面与聊天管理

- 形成白/黑主色与 `#8db95a` 强调色的 HammerCode 界面和品牌资产。
- 左侧按当前工作区管理多条独立聊天，不再把工具调用误当作聊天列表。
- 对话中实时展示思考和工具链，结束后折叠过程并以 Markdown/GFM 渲染最终回答。
- 每条聊天独立持久化，旧版单会话数据可安全迁移。

### 阶段二：连续对话、变更审查与撤销

- 同一聊天支持多个 turn；`completed`、`cancelled`、`failed` 都可由新的用户输入安全继续。
- 所有消息、工具轨迹和状态转换带 turn 归属，界面逐轮呈现。
- 恢复时闭合未完成 tool call，并保证历史工具永不自动重放。
- 已批准的文本文件创建、修改和删除形成可逆 `FileChange` 记录。
- 按文件合并多次变更，展示从首次 before 到当前有效状态的累计 diff。
- 撤销生成反向 diff 并再次审批；通过路径顺序、磁盘哈希和执行前复查阻断过期撤销。
- 撤销中断后只做磁盘状态对账，不重放反向副作用。

## 当前质量状态

- TypeScript 主进程、渲染进程和测试配置均采用严格类型检查。
- 自动测试覆盖状态转换、流式工具组装、路径边界、审批策略、命令生命周期、上下文预算、连续 turn、中断恢复、重复副作用阻断、累计 diff 和安全撤销。
- 发布前固定执行：`npm run typecheck`、`npm test`、`npm run build`、`npm run package:mac`。

## 下一阶段候选项

- 为超长聊天补充更细粒度、可观测的分层上下文压缩策略。
- 增加变更记录的持久化配额与旧内容淘汰策略，避免长生命周期聊天无限增长。
- 为命令执行后的工作区变化提供只读检测报告，但不承诺自动撤销任意命令副作用。
- 完成 macOS App Sandbox、签名与公证方案评估。
- 在复用同一模型端口和 agent core 的前提下评估 strong 模型路由，首版仍只维护 OpenAI-compatible 协议边界。
