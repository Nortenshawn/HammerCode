# HammerCode 迭代开发状态

最后更新：2026-08-30

## 当前结论

HammerCode 已完成 Phase 11 的 Skill 信任与激活收敛。外部兼容标准 `SKILL.md` 包、可选 `agents/openai.yaml` 和本地导入导出，内部发现、模型选择、上下文注入、权限和审计均由 HammerCode 自行实现。显式 `$skill-name` 直接优先；未显式指定时模型只获得有界名称/description 目录，必须调用 `activate_skill` 才会加载正文。项目 Skill 信任绑定全包内容 SHA-256，任意文件变化后自动撤销；`allowed-tools` 永不授权，部分不兼容脚本可迁移但不能执行。

### 阶段九：项目长期记忆与受限多 Agent

- 状态：已完成（2026-08-29）。
- 项目记忆按工作区真实路径隔离持久化，记录类型、主题、陈述、置信级别、来源、冲突和失效条件。成功文件修改自动形成哈希绑定事实，验证结果绑定工作区修订；外部编辑或后续文件修改会使对应旧事实失效。
- 每轮请求只注入有界、相关、带来源的不可信记忆；模型可以检索和记录明确标为 `model_inference` 的决定/约束，不能伪造工具核验。设置页可查看有效/冲突/失效状态并软删除记录。
- 主 Agent 单个 turn 累计最多创建三个子任务。子任务拥有独立状态、Plan、模型、权限快照、轮次/工具/时间/上下文预算、消息审计和结构化结果；父任务停止会取消全部活动子任务，重启后不会续跑或重放。
- 首轮子 Agent 只允许计划、目录/文件/PDF读取、搜索和只读 Git；不存在递归编排、通用命令、项目记忆或直接写入工具。`patch_proposal` 只能生成带 before/after hash 的候选 diff，不落盘。
- 主写入与补丁提案共享规范化路径租约，同一路径同一时刻只能有一个 owner；拒绝、失败、取消和完成都会释放。主 Agent 的真实写入继续经过审批/完全访问、过期哈希与工作区边界，远端命令即使完全访问也始终逐次审批。
