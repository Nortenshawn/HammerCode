# HammerCode 架构与安全设计

## 设计目标

HammerCode 首版只解决一个闭环：用户选择一个本地工作区，给出任务，模型通过本地工具获取事实、提出修改并验证，用户可以看见并控制每个副作用。

核心层不依赖 Electron。模型客户端、工具执行器、审批器、时钟和 ID 生成器均通过显式端口注入，因此自动测试能稳定覆盖失败、拒绝和取消分支。

## 进程边界

```text
Renderer（仅展示与交互）
        │ 最小、带类型 IPC
        ▼
Preload（contextBridge）
        │
        ▼
Electron Main
  ├─ AppController / SessionStore
  ├─ DeepSeekChatClient
  └─ AgentRunner
       ├─ Context manager
       ├─ Tool executor
       ├─ Workspace boundary
       └─ Approval gateway
```

renderer 使用 `nodeIntegration: false`、`contextIsolation: true` 和 `sandbox: true`。preload 只暴露选择工作区、新建/选择聊天、开始/取消任务、审批、清空会话和接收安全快照等明确操作。它不能读取文件、执行任意命令或访问环境变量。

API key 只由 main process 从环境变量或 `.env` 加载。公开配置只包含是否已配置 key，不包含值。网络错误进入 UI 前会清理 bearer token、常见 key 模式和 URL 敏感查询参数。

## Agent 循环

每轮流程为：

1. 根据预算构建模型上下文。
2. 请求 OpenAI-compatible `/chat/completions` 流并逐片展示思考与文本。
3. 按 tool call 索引组装 `id`、函数名和 JSON 参数。
4. 若模型正常 `stop`，会话完成；若请求工具，则逐个校验并执行。
5. 只读工具自动执行。写入、删除和命令进入审批；拒绝作为结构化 tool result 回传模型。成功的文本文件副作用同时写入可逆变更记录。
6. 工具结果加入消息历史，开始下一轮。达到轮次上限即失败终止，不会无限循环。

`length`、`content_filter`、`insufficient_system_resource`、无效分片、上下文溢出、网络错误和用户取消都有明确终止路径。

聊天与 agent 执行不是一一对应关系。一个聊天由多个 `AgentTurn` 组成；每条消息、工具轨迹和状态转换都带 `turnId`。终态会话只有在用户再次发送消息时才能进入新 turn，并为新 turn 重置轮次计数。模型可以看到经过预算处理的历史，但 runner 只执行当前响应流中新组装的 tool call。恢复时若发现历史 tool call 没有对应结果，会幂等补入 `TOOL_CALL_INTERRUPTED`，使协议历史闭合且不产生副作用。

## 文件安全

工作区初始化时先取得根目录真实路径。每次访问都要求模型提供相对路径，并完成：

- 拒绝绝对路径、NUL 和词法 `..` 逃逸；
- 对已存在目标调用 `realpath`，确认仍位于根目录；
- 对不存在写入目标向上寻找最近存在父目录并验证真实路径，阻止“symlink 目录 + 新文件”逃逸；
- 写入审批后再次校验路径，并比较审批预览时的 SHA-256；文件在等待期间变化则拒绝落盘；
- 使用同目录临时文件、`fsync` 和原子 rename 完成写入；
- 删除只接受单个普通文件，并在审批后比较 inode、大小和修改时间。

上述检查降低了路径穿越、符号链接逃逸和审批后竞争风险。它们不能替代操作系统权限边界，因此正式分发仍应考虑 macOS App Sandbox 与签名能力。

## 变更审查与撤销

每次已批准且执行成功的文本文件创建、完整替换或删除都会形成 `FileChange`。记录包含路径、变更种类、before/after 内容及 SHA-256、原始 patch、所属 turn 和 applied/reverted 状态。renderer 按路径归并记录，从首次 before 状态到当前有效 after 状态生成累计 diff，因此连续修改不会变成一串难以阅读的工具卡片。

撤销遵循乐观并发检查：只能选择同一路径最新的 applied 变更，准备阶段先确认磁盘哈希仍等于其 after 哈希，再通过同一个本地工具执行器生成反向操作与 diff。反向操作仍需审批，执行前再次比较哈希。若用户在审批期间编辑了文件，撤销会以 stale 结果停止。

待审批和执行中的撤销会随会话持久化。进程重启后仅根据当前磁盘哈希完成三态对账：等于 before 说明反向操作已经成功，等于 after 说明尚未执行，其他值说明存在外部变化。恢复路径绝不自动重放反向操作。

## 命令安全与生命周期

所有通用命令都需要审批，界面展示完整命令、绝对 cwd 和超时。提权、系统关机、磁盘擦除、危险根目录删除和持久化系统服务等模式在审批前直接阻断。

命令通过独立进程组启动。超时或取消时先向整个进程组发送 `SIGTERM`，随后发送 `SIGKILL`；这样能同时清理 shell 及其子进程。stdout/stderr 有总字节上限，结果记录退出码、信号、耗时、超时和截断标记。

## 上下文与持久化

Token 估算采用保守字符启发式，不假装等于厂商 tokenizer。超过预算时保留初始用户目标和最近消息，把较早内容转换为明确标注的“本地压缩摘要”；压缩后仍超预算则终止，不发送不可控请求。

会话快照区分 turn、用户消息、助手消息、tool call、tool result、状态转换、文件变更和终止原因。单个工作区可以保存多条独立聊天，由小型索引记录当前选中项，每条聊天分别使用 0600 权限临时文件加原子 rename 保存。启动时如果发现任一聊天上次状态为请求中、待审批或执行中，会闭合未完成的 tool call、标记为 `interrupted/failed`，不会继续或重放副作用；旧版单会话文件会在首次启动时安全迁移并补齐 turn 归属。

## 当前限制

- 首版为单窗口、单工作区，可保存多条独立聊天；不实现多工作区、多 agent、MCP 或插件。
- 文本搜索是本地安全实现，优先可靠性而非大型仓库索引性能。
- 当前写工具是完整文本文件替换；二进制文件及大于 1 MB 的文件不支持写入、删除审查或撤销。
- 撤销粒度是单次文件副作用，不是 Git commit；命令产生的文件变化不进入自动撤销记录。
- 高风险命令阻断采用明确规则集，不能证明任意 shell 字符串安全，因此剩余命令始终要求人工审批。
- Token 预算为估算值；服务端仍可能因其 tokenizer 或动态限制返回长度错误。
