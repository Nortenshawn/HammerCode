## 文件职责

本文件是 HammerCode 当前范围、优先级、执行顺序和验收出口的唯一动态来源。`AGENTS.md` 维护长期安全与工程底线，`DEVELOPMENT_STATUS.md` 记录已经完成的历史，`ONLINE_TEST_REPORT.md` 保存真实模型验收证据。

计划调整时应直接修改本文件，不再把阶段性“不实现”写成永久项目约束。每项进入开发前必须明确用户价值、架构影响、风险、离线测试和在线验收方式；完成后附上提交与验证证据。

## 当前阶段：Phase 4 · 双模型、权限模式与多工作区

状态：已完成（2026-08-28）。Fast、Strong、权限模式与多工作区均已通过真实桌面闭环，不做隐式模型回退。

用户价值：

- `fast` 使用 `deepseek-v4-flash`，承担低延迟日常任务；`strong` 使用 `glm-5.3-flash`，承担复杂任务。模型由用户显式选择，不做隐式路由或失败回退。
- `请求批准` 保持逐项确认；`完全访问` 让受信任工作区中的连续开发无需反复点击，同时不削弱目录边界和高风险命令禁令。
- 侧栏可以维护多个本地项目，每个文件夹下拥有独立聊天集合；单条聊天仍严格绑定一个工作区。

架构与迁移：

1. 把单模型配置升级为 `fast` / `strong` 两份 provider 配置；agent core 继续只依赖 `ModelClient`，main process 在每轮开始前创建选定客户端。
2. DeepSeek 与 GLM 复用同一 OpenAI-compatible SSE 和 tool call 组装器，由 provider profile 生成合法请求字段。GLM 开启 `tool_stream`，且 `thinking.type` 固定为 `enabled`。
3. 增加 `ModelTier = "fast" | "strong"` 与 `PermissionMode = "ask" | "full_access"`。聊天保存下一轮偏好，每个 turn 保存本轮快照；运行中禁止修改。
4. 工具轨迹增加授权来源，明确区分 `not_required`、`user_approved`、`user_rejected`、`full_access` 和 `safety_blocked`。完全访问只跳过审批网关，不跳过工具 prepare 阶段的路径和命令安全检查。
5. `session-index.json` 从单工作区 v1 迁移为多工作区 v2。索引记录当前项目、每个项目的聊天 ID、活动聊天和最近使用时间；聊天文件仍按 ID 独立保存。
6. 旧索引、旧聊天、旧 turn 和旧工具轨迹必须无损迁移：缺失模型档位默认为 `fast`，缺失权限模式默认为 `ask`，旧审批轨迹按现有状态推导授权来源。
7. renderer 只通过带类型 IPC 选择项目、聊天、模型和权限。真实凭据仍只存在于 main process；缺少某一档凭据时只禁用该档并给出明确配置提示。

风险控制：

- 不允许在模型失败时静默换档；错误必须指明所选档位与失败阶段。
- 不允许一条聊天跨工作区访问，也不允许通过多工作区索引扩大本轮工具根目录。
- `full_access` 不能批准 `sudo`、磁盘擦除、关机等高风险命令，也不能批准路径穿越、绝对路径或 symlink 逃逸。
- 首次切换完全访问必须显示一次警告；正在运行、等待审批或撤销时，模型与权限选择器均锁定。
- 撤销继续使用可见反向 diff 和独立确认，不因聊天处于完全访问而自动执行。

离线测试：

- 两个 provider 的请求体、SSE 文本、思考内容、分片 tool call、`[DONE]`、HTTP 错误和取消。
- 每轮模型/权限快照、旧数据默认迁移、运行中不可切换、缺少 strong 凭据时不回退。
- `ask` 的批准/拒绝，`full_access` 的自动批准，以及两种模式下相同的高风险与路径阻断。
- 多工作区 v1 → v2 迁移、空项目、项目切换、每项目活动聊天、删除聊天和重启恢复。
- renderer 的项目导航、模型/权限选择器、首次警告和工具授权标签。

在线退出标准：

- 在 `/Users/norten/Developer/HammerTest` 使用真实 DeepSeek 完成 `fast + ask` 与 `fast + full_access` 的读、写、命令和安全阻断闭环。
- 在同一沙箱使用真实 GLM-5.3-Flash 完成 `strong` 的流式思考、分片工具调用、文件修改和命令验证；若本地未配置 GLM 凭据，必须记录为明确阻塞，不能用模拟测试冒充通过。
- 添加第二个临时工作区，证明项目与聊天可以切换、重启后恢复，且工具不能跨项目访问。
- 工具轨迹可见地区分用户批准、用户拒绝、完全访问自动批准和安全策略阻断。
- `npm run typecheck`、`npm test`、`npm run build` 和 Apple Silicon 打包全部通过。

完成证据：共享 OpenAI-compatible 客户端、双模型配置、逐 turn 模型/权限快照、授权来源审计和多工作区 v2 索引均已落地。真实 `deepseek-v4-flash` 已完成 `fast + ask`、`fast + full_access` 和完整五子棋开发闭环；真实 `glm-5.3-flash` 已在完全访问模式完成 1/12 失败基线到 12/12 通过的状态管理修复，四次 `edit_file` 和普通命令均保留授权来源。在线失败没有静默回退：GLM 超时促使默认请求超时提高到 600 秒，用户主动停止保留独立取消来源。详见 `docs/ONLINE_TEST_REPORT.md`。

## 当前阶段：Phase 5 · Codex 风格交互与编辑可靠性

状态：已完成（2026-08-28）

用户价值：

- 以白/黑为主、`#8db95a` 为唯一强调色，形成克制、清晰的桌面 agent 界面；提高字号和信息密度，移除旧黑金视觉。
- 左侧按项目组织聊天，项目文件夹右侧可直接新建聊天；任务运行时允许切换项目和聊天，不必等待当前请求结束。
- 思考、工具调用和模型文本实时流式展示，任务结束后过程自动折叠，最终回答使用 Markdown/GFM 渲染。
- 文件审查不覆盖主工作区。点击文件后打开并排右栏，主聊天与 diff 约按黄金比例共同压缩，红绿行差异和累计增删统计保持可见。
- 输入区右下角是唯一可点击的停止入口；顶部只展示计时状态，降低窗口变窄时误触取消的风险。

架构与实现：

1. renderer 使用单一三列 grid：项目栏、主聊天和可选 diff 栏；审查栏不是 fixed overlay，窄宽度下仍通过最小列宽共同收缩。
2. SessionStore 支持后台保存而不改变活动项目/聊天；Controller 将 agent 执行 ID 与导航选中项解耦，并用独立 `session_updated` 事件更新后台摘要。
3. 加载导航时显式传入当前存活 session ID，避免把仍在运行的任务当成重启残留执行中断恢复。
4. 增加 `edit_file` 精确文本替换工具：要求唯一匹配，零匹配、多匹配、空操作和过期哈希均安全失败，并复用写入审批、原子落盘和撤销链路。
5. 流式滚动采用用户意图感知：用户离开底部后停止自动跟随，并提供“查看最新进度”；结束后展示精确耗时。

退出标准与证据：

- 真实 Electron 界面中从项目行 `+` 直接创建聊天成功。
- Fast 任务运行时切换到另一项目聊天，再切回后仍连续流式运行；5 次只读工具调用在 16 秒后正常完成，没有误标记中断或重复执行。
- Strong 真实调试任务使用 `edit_file` 四次，最终 12/12 测试通过；累计 diff 显示 `+144/-16`，并排审查栏视觉验收通过。
- 自动测试覆盖后台保存不抢占导航、`edit_file` 的成功与错误分支、取消原因、双 provider 上限和文件增删统计；最终检查结果见本轮提交与 `DEVELOPMENT_STATUS.md`。

## 当前阶段：Phase 6 · 可交付运行与长任务编排

状态：已完成（2026-08-28）

用户价值：

- 增加“设置”入口，允许用户只填写 OpenAI-compatible API URL 与 API key；应用主动读取模型列表并验证鉴权与协议连通性，保存后可直接选择发现的模型，不要求用户理解中转站的额外参数。
- 复杂任务显式维护可见、可持久化的 Plan。模型通过专用本地工具更新步骤状态，每次更新形成进度检查点；重启、失败和继续聊天后均保留真实进度。
- 长任务面对 429、5xx 和临时资源不足时执行有界退避重试，同时清楚区分请求超时、输出预算耗尽、用户停止、限流、资源不足和服务端异常。
- 界面持续展示轮次、模型请求/重试、输出 token、工具次数和总运行时间及其预算，避免长任务成为不可解释的黑盒。
- 命令权限从“普通/危险”升级为三层：可证明的本地验证与只读 Git 可自动执行，远端变更始终审批，提权、磁盘擦除、关机和越界继续直接阻断。

架构与安全边界：

1. 新增独立 `ApiConnectionStore`。API key 只允许从设置表单单向提交给 main process，使用 Electron `safeStorage` 加密后保存；renderer、公开配置、日志、错误和会话文件只接收连接 ID、脱敏 URL、模型 ID 与测试状态，不提供密钥读回接口。系统加密不可用时拒绝持久化，不回退到明文。
2. 自定义连接只接受 HTTPS，或本机 loopback HTTP；拒绝 URL 中的用户名、密码、查询参数和片段。连通性检测使用 Bearer 鉴权访问标准 `/models`，严格限制超时与响应大小，并把 401/403、协议不兼容、网络失败和超时分别报告。
3. 会话模型选择升级为稳定 `modelRef`：内置 Fast/Strong 保持兼容，发现的自定义模型使用连接 ID + 模型 ID 引用。每个 turn 固化实际连接、模型和预算；删除仍被历史引用的连接不会泄露密钥，后续继续时必须重新选择可用模型。
4. `AgentTurn` 持久化 `plan`、`planCheckpoints` 和运行指标。专用 `update_plan` 工具只能更新当前 turn 的结构化步骤，不读写工作区；复杂任务在首次副作用前必须建立计划，计划更新和工具结果一样进入历史但不会被恢复逻辑重放。
5. AgentRunner 负责重试编排与预算：默认最多 2 次重试、指数退避且单次等待有上限；只重试 429、5xx 和 `insufficient_system_resource`，不自动重试用户停止、请求超时、内容策略或输出长度耗尽。重试前不提交半截 assistant/tool call，不会产生重复本地副作用。
6. 增加每 turn 最大工具次数和最大运行时间；触达轮次、工具或时间上限时以独立终止原因停止。失败后的下一条用户消息创建新 turn，复用已持久化事实与计划检查点，但 runner 仍只执行新响应中的 tool call。
7. 上下文压缩从自由文本截取升级为事实分区摘要，明确保留：原始目标、最新用户约束、已完成文件变更、验证结果、失败错误、当前计划与未完成步骤。工具调用及其结果继续作为不可拆分协议组；摘要始终标记为本地生成，不伪装成模型事实。
8. 新增 `git_status` 与 `git_diff` 专用只读工具。通用命令先经语法级风险分类：确定的本地测试/类型检查可自动执行；`git push`、部署、发布、上传和其他远端状态修改始终审批，即使聊天为完全访问；高风险命令直接阻断。

离线测试：

- API URL 校验、加密凭据不回传、`/models` 正常/401/429/5xx/超时/超大或畸形响应，以及自定义模型引用迁移。
- Plan 创建、步骤更新、非法状态转换、检查点持久化、复杂任务副作用前计划门槛、重启恢复和失败后继续。
- 429/5xx/资源不足退避上限、Retry-After 截断、超时不重试、半截流重试不提交、用户取消打断等待。
- 独立终止原因、轮次/工具/运行时间预算、usage 累加和界面安全快照。
- 压缩后保留目标、最新约束、已应用文件、验证结果、错误与未完成计划，并保持 assistant tool call/result 原子性。
- 命令三层分类、完全访问仍审批远端操作，以及 `git_status`/`git_diff` 的仓库内只读、超时和输出上限。

在线退出标准：

受限多 Agent：

1. 现有 AgentRunner 是唯一协调 Agent。单个主 turn 累计最多创建 3 个子任务，每次批量 1–3 个；禁止子 Agent 获取创建子 Agent 的工具，因此不能递归编排。
2. 首个正式闭环的子 Agent 固定为只读分析、测试定位和代码审查。它们只能使用计划、目录、文本/PDF读取、搜索和只读 Git 工具；不能运行通用命令、写文件、审批、访问项目记忆写入口或改变远端状态。
3. 每个子任务独立保存任务、角色、模型、父权限快照、实际权限、轮次/工具/时间/上下文预算、状态、Plan、工具审计、结果和取消原因。父任务取消时必须取消全部活动子任务。
4. 子 Agent 最终输出解析为结构化结论，包含摘要、发现、证据、相关文件、验证建议和风险。协调 Agent 的 tool result 只接收该结构化结果与预算摘要，不接收子 Agent 的完整消息或原始工具输出。
5. 子任务模型默认继承父 turn 的明确模型选择；`full_access` 不向子 Agent 扩大，首个闭环实际权限始终为 `read_only`。

3. 子 Agent 永远不获得 `git push`、部署、发布、上传或其他远端工具。主 Agent 的远端命令继续由 `always` 风险层强制逐次审批，`full_access` 不能绕过。

风险与测试：

## 当前阶段：Phase 11 · 可控、本地、渐进加载的 Skill 系统

状态：已完成（2026-08-30）

用户价值：

1. Skill 是可迁移的本地工作流能力包。对外兼容 Agent Skills 标准目录：唯一必需文件是带 `name`、`description` frontmatter 的 `SKILL.md`，目录名与 `name` 一致；`references/`、`scripts/`、`assets/` 及其他非隐藏附加资源均可原样迁移。内部发现、激活、上下文注入、权限与审计全部自主实现，不另设会妨碍 GitHub 导入或向其他 Agent 导出的必需 manifest。
2. 常驻索引只保存名称、`description`、版本、来源与兼容元数据。输入 `$` 打开 Skill 补全，选择后生成不带前缀噪音的原子输入块；`/skills` 打开设置中的 Skill 列表。显式 `$skill-name` 优先并直接加载。未显式指定时向模型提供最多 8,000 字符的有界元数据目录，由模型通过 `activate_skill` 选择最多一个明确匹配项，不再使用字符串命中或关键词计分冒充“自动选择”。
3. Skill 分为随应用发布的内置来源、HammerCode 用户数据目录中的用户来源，以及当前工作区 `.agents/skills/` 中的项目来源。项目 Skill 不跨工作区，信任绑定由每个文件内容 SHA-256 形成的完整包指纹；任意文件增加、删除或修改后立即禁用并撤销信任，重新启用必须确认新指纹。
4. 设置页支持本地文件夹导入、启用/禁用、查看版本、来源、License、兼容声明、兼容级别、最近使用时间、结构检查、导出及卸载。格式有效但含非 Python 脚本、额外依赖或未接入工具的包允许迁移并标记“部分不兼容”，不可执行项不会进入运行清单。当前仍不提供市场、网络安装、依赖下载、自我修改、递归调用或远程 Skill。

架构与渐进加载：

1. main process 的 `SkillStore` 负责索引、校验、信任状态、导入导出和按需资源读取。renderer 只接收脱敏的公开清单，不接收 Skill 绝对存储路径或任意文件访问能力。
2. `AgentRunner` 在 turn 启动时固化显式 Skill，或固化可供模型选择的 ID、来源、版本和包指纹目录；`activate_skill` 成功后才把完整入口加入本轮消息链与审计。Skill 默认只对当前 turn 生效，后续更新和启停只影响下一轮；历史恢复不重新选择或重放任何工具。
3. Skill 指令以明确的不可信低优先级区块注入，优先级固定为：系统安全边界 > `AGENTS.md` > 当前用户要求 > 当前 turn Plan > Skill 指令 > Skill references。Skill 内容不能覆盖安全策略，也不能把 references 伪装成事实。
4. 本轮最多加载 2 个显式 Skill 或由模型选择 1 个 Skill；目录、入口、references、脚本输出分别设字符/token 上限。turn 指标记录目录成本、实际使用数量、入口与按需资源的字符数和估算 token。聊天压缩只保留使用过的 ID/版本、触发来源和关键结论，不保留完整说明书。
5. `read_skill_resource` 只能读取本轮已选择包内已校验的相对资源，拒绝绝对路径、`..`、符号链接、读取竞态和包指纹变化。`run_skill_script` 只能运行本轮已发现并固化在包内清单的文本脚本；审批前固化已校验代码快照，避免等待期间被替换，并经过静态高风险/凭据/网络检查，复用原有 `ask/full_access`、命令超时、输出上限、取消和授权审计。
6. BTW 不执行 Skill 选择、不注入 `SKILL.md`、不暴露 Skill 资源或脚本工具；它只能单向读取创建时已存在的主线可见事实。

威胁模型：

- 所有 Skill 文件均视为不可信输入。目录扫描限制文件数量、单文件/总大小和允许结构；拒绝符号链接、隐藏依赖、越界入口、重复 ID、缺失入口和不合法 manifest。二进制 asset 只允许有界迁移，不注入模型也不执行。
- 入口和 references 中诱导读取 `.env`、API key、凭据、工作区外绝对路径，或要求忽略系统/用户/`AGENTS.md` 的内容在启用或加载前阻断。
- 脚本不得包含提权、磁盘擦除、系统关机、远程命令、上传、发布、凭据读取、任意子进程或网络访问能力；项目 Skill 即使在完全访问聊天中也不能绕过这些直接阻断。

## Phase 16 范围调整：多项目并行主任务

状态：已完成（2026-08-31）

用户价值：

1. 不同工作区中的普通聊天可以同时运行彼此独立的主 Agent。用户可在一个项目等待模型或审批时切换到另一个项目继续工作，切回后仍看到原任务的真实流式状态、Plan、工具轨迹和停止入口。
2. 全局主 Agent 并发上限集中在运行配置中，默认且硬上限为 3。同一工作区首版仍只允许一个主 Agent；第二条聊天必须明确拒绝，不能在没有 Git worktree 隔离时共享写入边界。
3. 左侧聊天只增加紧凑状态标记，其中等待审批必须可辨认；不新增任务中心，也不改变 BTW、隔离子 Agent 或项目记忆的产品语义。

架构边界：

1. AppController 使用以 `sessionId` 为键的主任务运行注册表替代全局 runner、审批器和 runningSessionId。每个注册项独立持有 AgentRunner、PendingApprovalGateway、AbortController、工作区真实路径、模型连接/权限/预算快照及最新 session；工作区预留必须在异步创建边界前完成，避免并发启动竞态。
2. 注册表同时建立 `workspaceRoot → sessionId` 唯一占用关系，并把“正在启动”的预留计入全局上限。完成、失败、取消和启动异常必须幂等释放；后台快照只更新对应会话摘要与持久化文件，只有 sessionId 与当前导航一致时才能更新主视图。
3. `cancelTask` 与 `resolveApproval` IPC 必须显式携带 sessionId。main process 同时校验 sessionId、approvalId 和对应运行项；A 聊天不能停止、批准或拒绝 B 聊天。当前聊天的撤销审批继续沿用既有机制，但不得借用主任务审批注册项。
4. SessionStore 恢复接收全部活动 sessionId；应用运行期间刷新导航不得把后台任务误判为中断。应用退出时遍历取消全部注册项；下次冷启动没有 live session，仍按既有 interrupted 语义封口未完成工具，禁止自动续跑或重放。
5. AgentRunner、模型客户端、LocalToolExecutor、WorkspaceBoundary、WorkspaceWriteLeaseManager、子 Agent coordinator 和 turn 预算仍按主运行实例独立创建。不同项目不共享审批、取消、流式状态或写租约；同一项目并行主任务、worktree 创建、跨 Agent 通信、迁移与分布式调度不在本阶段实现。

风险与控制：

1. 启动竞态：两个 IPC 可能在第一个 sessionId 生成前同时进入。通过同步工作区预留和全局容量预留原子拒绝；任何失败路径都释放预留。
2. 审批串线：同时出现多个 pendingApproval 时，renderer 只展示当前聊天的审批，侧栏提示其他等待项；提交审批必须同时携带当前 sessionId 与 approvalId，main 再按注册项匹配。
3. 导航抢占：后台 `onSessionChange` 永远发送 `session_updated`，不得改变当前 workspace/session 或 store 的 active 指针；当前会话才发送 `session_snapshot`。标题生成也按 registry 判断任务是否仍活动。
4. 恢复误判：每次 loadState 都传入注册表全部 sessionId；关闭时向全部运行项发送取消。若进程退出前来不及持久化终态，冷启动统一按 interrupted 封口，仍不续跑。
5. 资源与远端风险：每个实例继续遵守自己的模型/轮次/工具/时限预算；总并发不放宽工作区边界、命令风险、远端审批、Skill 脚本隔离或子 Agent 上限。

自动测试：

- 两个不同工作区主 Agent 能并行推进；一个等待审批时另一个继续完成；停止一个不影响另一个。
